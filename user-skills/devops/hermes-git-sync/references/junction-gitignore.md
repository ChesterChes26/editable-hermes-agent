# Junction .gitignore Template (Whitelist Strategy)

Add to `hermes-agent/.gitignore` after setting up reverse junctions.

## Strategy: Three-Layer Pattern

**Problem**: Simple `dir/*` + `!dir/*/FILE` doesn't work for nested directories.
Git won't traverse into subdirs if they're ignored at the first level.

**Solution**: Three layers:
1. `dir/*` — ignore files at root level
2. `!dir/*/` — allow traversal into ALL subdirs (critical!)
3. `dir/**/PATTERN` — ignore specific unwanted files at ANY depth
4. `!dir/*/SAFE_FILE` — whitelist safe files

## What gets tracked (implicit whitelist)

After the deny+traverse+deny pattern above, these are tracked by default:
- `user-skills/*/SKILL.md` — skill definitions
- `user-skills/*/references/**` — skill reference docs
- `user-skills/*/templates/**` — skill templates
- `user-plugins/*/*.py` — plugin source
- `user-plugins/*/plugin.yaml` — plugin config
- `user-config/hooks/*/*.py` — hook source
- `user-config/hooks/*/HOOK.yaml` — hook config
- `user-config/scripts/*.py/.sh/.bat` — scripts
- `user-config/memories/USER.md` — user preferences (default profile only)

## What is explicitly excluded

- `DESCRIPTION.md` — auto-generated by Hermes curator
- `snapshots/` and `_example_snapshots/` — runtime outputs from computer-use skills
- `MEMORY.md` — technical notes (not for Git)
- `*.lock`, `.usage.json`, `.bundled_manifest` — runtime state
- `profiles/*/memories/*` — contains Bearer tokens, platform account IDs
- `config.yaml` — contains API keys
- `cron/jobs.json` — runtime state changes frequently

## Verification

After applying, verify rules work correctly:

```bash
cd ~/.hermes/hermes-agent

# Should NOT be ignored (tracked):

```

## Key pitfalls

1. **Order matters**: `!dir/*/` MUST come before `dir/**/PATTERN`
2. **DESCRIPTION.md**: Always ignore — Hermes curator auto-generates these
3. **Nested skills**: Use `**/` for depth-agnostic matching (skills can be 2-4 levels deep)
4. **Profile skills**: Need same traversal pattern as user-skills/
