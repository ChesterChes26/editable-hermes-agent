# Long-Running Sleep Cycle Management

## Problem Context

Sleep cycles for skill optimization can take 15-20 minutes per night (20 tasks × 4 LLM calls per task). ⛔ **1 command = 1 night** — `run_sleep_cycle()` in `cycle.py:91` has no internal loop. To run multiple nights, invoke the command multiple times (shell loop or cron). During execution, several issues can occur:

- Claude CLI times out after 180 seconds in the consolidate phase
- Python processes become zombie processes after timeout
- Multiple staging directories accumulate, making it unclear which is the latest/best
- Subagents may return truncated or garbled output after long runs

## Solution: Subagent Delegation Pattern

### 1. Delegate to Subagent (Never Run in Foreground)

```python
delegate_task(
    goal="Execute SkillOpt-Sleep optimization run",
    context="""
    Project path: D:\\workspace\\outlook-tencent-metting
    SkillOpt source: D:\\workspace\\SkillOpt
    Task file: tasks.v2.json (15 tasks, reviewed=true)
    Target skill: .claude/skills/computer-use/outlook-tencent-meeting-hybrid-en/SKILL.md
    Claude home: .skillopt-exp/outlook-tencent-meeting-hybrid-en/claude-home
    Backend: claude (requires ANTHROPIC_API_KEY=***
    Parameters: --max-tasks 20 --edit-budget 4 --progress --json
    Expected duration: 30-60 minutes
    """,
    background=True,
    notify_on_complete=True
)
```

### 2. Monitor Progress (Optional)

```python
# Check if process is running
terminal("ps aux | grep 'skillopt_sleep run' | grep -v grep")

# Poll specific process (if you have the session_id)
process(action="poll", session_id="proc_...")
```

### 3. Verify Results After Completion

**Don't rely on subagent summary** — it may be truncated or garbled. Instead:

```python
# List staging directories (most recent first)
terminal("cd /path/to/project && ls -lt .skillopt-sleep/staging/ | head -5")

# Read the latest report
read_file(path="D:\\workspace\\outlook-tencent-metting\\.skillopt-sleep\\staging\\YYYYMMDD-HHMMSS\\report.md")

# Check key metrics:
# - baseline_score vs candidate_score
# - gate decision (accept/reject)
# - accepted edits count
# - rejected edits count
```

### 4. Apply Successful Optimizations

If gate decision is `accept_new_best`:

```python
# Adopt the changes
terminal("""
cd /path/to/SkillOpt && python -m skillopt_sleep adopt \\
  --project "D:/workspace/outlook-tencent-metting" \\
  --claude-home "D:/workspace/outlook-tencent-metting/.skillopt-exp/outlook-tencent-meeting-hybrid-en/claude-home" \\
  --target-skill-path "D:/workspace/outlook-tencent-metting/.claude/skills/computer-use/outlook-tencent-meeting-hybrid-en/SKILL.md" \\
  --staging "D:/workspace/outlook-tencent-metting/.skillopt-sleep/staging/YYYYMMDD-HHMMSS"
""")

# Commit and push
terminal("""
cd /path/to/project && git add .claude/skills/.../SKILL.md CLAUDE.md && \\
git commit -m "Apply SkillOpt-Sleep optimization (night N, staging YYYYMMDD-HHMMSS)

- baseline: X.XXX → candidate: Y.YYY (+Z.Z%)
- gate: accept_new_best
- Added N new rules to SKILL.md

Generated by SkillOpt-Sleep with tasks.v2.json (15 tasks)" && \\
git push origin restore-skills
""")
```

## Handling Timeouts and Zombie Processes

### Symptom: Claude CLI Timeout (Exit Code 2304)

```
Claude CLI could not be executed: Command '['...claude.CMD', ...]' timed out after 180 seconds
```

**Diagnosis**: The consolidate phase makes multiple LLM API calls and exceeded the 180-second timeout.

**Check if process is still running**:
```bash
ps aux | grep "skillopt_sleep" | grep -v grep
```

**If zombie process exists, kill it**:
```bash
# Unix/Linux/macOS
pkill -f "python.*skillopt_sleep"

# Windows (PowerShell)
Get-Process python | Where-Object {$_.CommandLine -like "*skillopt_sleep*"} | Stop-Process -Force

# Windows (CMD)
taskkill /F /PID <pid>
```

**Check for partial results**:
Even if the process timed out, check the staging directory — sometimes the run completed despite the timeout error:
```bash
ls -lt .skillopt-sleep/staging/ | head -5
cat .skillopt-sleep/staging/YYYYMMDD-HHMMSS/report.md
```

### Symptom: Multiple Staging Directories

After many runs, you'll have multiple staging directories. Don't assume the latest is the best.

**Multiple staging dirs per night**: During the consolidate phase, the process may generate multiple staging directories for the same night (observed: night 21 produced 3 directories over 6 minutes — 07:35, 07:40, 07:41 — each with different rejected edits as the LLM iterated). The **final** staging directory (most recent timestamp for that night) is the authoritative result. Check state.json to confirm which night completed and what the final staging path is:

```python
import json
state = json.load(open(".skillopt-sleep/state.json"))
last = state["history"][-1]
print(f"night={last['night']}, staging={last['staging']}, accepted={last['accepted']}")
# The staging path in state.history[-1] is the final result for that night
```

**Find the best result across nights**:
```python
import os
import json

staging_dir = "D:\\workspace\\outlook-tencent-metting\\.skillopt-sleep\\staging"
dirs = sorted(os.listdir(staging_dir), reverse=True)  # Most recent first

for d in dirs[:5]:  # Check top 5 most recent
    report_path = os.path.join(staging_dir, d, "report.json")
    if os.path.exists(report_path):
        with open(report_path) as f:
            report = json.load(f)
        baseline = report.get("baseline_score", 0)
        candidate = report.get("candidate_score", 0)
        accepted = report.get("accepted", False)
        print(f"{d}: baseline={baseline:.3f} → candidate={candidate:.3f}, accepted={accepted}")
        if accepted:
            print(f"  → Best result! Adopt this staging directory.")
            break
```

## Key Metrics to Track

After each sleep cycle, verify:

1. **Baseline score**: Should be stable or improving across runs
2. **Candidate score**: Should exceed baseline for gate to accept
3. **Gate decision**: `accept_new_best` means the optimization improved the skill
4. **Accepted edits**: Number of rules added to SKILL.md
5. **Rejected edits**: Rules that didn't improve performance (kept as negative feedback)
6. **Token usage**: High token counts (>300k) may indicate inefficient consolidation

## When to Stop Optimizing

**Stop when**:
- Baseline score = 1.000 (perfect score on all tasks)
- Gate consistently rejects all candidate edits
- Multiple consecutive runs show no improvement

**Next steps**:
- Create a harder task set (tasks.v3.json) with more challenging scenarios
- Adjust evaluation criteria (e.g., stricter rubrics)
- Increase edit budget (--edit-budget 6 or 8)
- Try different optimization strategies (e.g., focus on specific failure modes)

## Example Session Flow

```
1. Delegate sleep cycle to subagent (background=true)
2. Wait for completion notification (30-60 min)
3. Verify results by reading staging report.md
4. If gate=accept_new_best:
   - Adopt changes
   - Commit and push
   - Report success to user
5. If gate=reject:
   - Check if baseline=1.0 (skill is optimal)
   - If yes, suggest creating harder task set
   - If no, retry with different parameters
6. Clean up zombie processes if timeout occurred
```

## Common Pitfalls

- **Running in foreground**: Will block for 30-60 minutes. Always use background delegation.
- **Trusting subagent summary**: Always verify by reading the actual report files.
- **Assuming latest staging is best**: Check all recent staging directories for the best result.
- **Not killing zombie processes**: Will accumulate and consume resources.
- **Forgetting to commit after adopt**: Changes are local until pushed to remote.
- **Ignoring rejected edits**: They contain valuable signal about what doesn't work.
